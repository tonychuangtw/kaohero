下面這些題當初被判定「不能寫一般詳解」，理由是**官方公布的答案與現行法規／教科書衝突，或修法後變成不只一個選項成立**。
這種題不寫解析會在站上留一片空白，考生自己算出「答案好像是別的」時完全沒有交代；硬寫成一般解析又會誤導。
所以改寫一段「勘誤提醒」：講清楚官方答案是什麼、為什麼現在看起來不對、現行的規定是什麼、考試時該怎麼辦。

只做一件事，然後結束：
用 Write 工具把結果寫到 __OUT__，內容是 JSON 陣列：
[{"pid":"…","n":題號,"note":"⚠ …"}, ...]
確定寫不出來的題就不要放進陣列（寧可少寫，不要寫錯）。檔案一定要寫，即使是空陣列。

note 格式硬規則（寫入工具會逐題檢查，錯一題整批退回）：
- 第一個字是 ⚠，全文 40～400 字，最多 4 行，繁體中文
- ⛔ 不可以出現 ✅ ❌ 📚（那是一般詳解的格式）
- 必須明講「官方公布答案是 (X)」
- 接著講衝突點：哪一年、哪一部法或哪一個定義改了、改成什麼，或哪兩個選項同時成立
- 最後給考生一句實用的話（例如：本題已不具參考價值、或依現行法應選 (Y)、或此考點已改制）

⚠️ **條號一定要自己確認過再寫**。下面每題附的「當初跳過的判斷」是別的模型寫的，
已知會出現掰出來的條號（2026-09-18 查證過）。**沒有把握的條號就不要寫**，改寫法規名稱與修法年份即可——
寫「民法成年年齡於 112 年 1 月 1 日起改為 18 歲」是安全的，寫錯條號會讓整段變成錯的。
同理，修法年份、金額、期間也一樣：不確定就用概括寫法，不要編數字。

判斷方式：
- 真的是「官方答案與現行法衝突」「修法後兩個選項都對」→ 寫 note
- 看了之後覺得官方答案其實沒問題（當初判斷有誤）→ 不要放進陣列
- 題目本身轉檔毀損、缺圖缺公式而無法判讀 → 不要放進陣列
